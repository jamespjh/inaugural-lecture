# Plan: Add Three-D Visualisation

## Issue
GitHub issue: Add three-D visualisation

## Summary

Extend the teachgrav demo to support 3-dimensional gravitational and boids
simulations, with matching 3-D visualisation, while keeping the code as DRY
as possible.

## Requirements

- Add visualization code with 3-d axes
- Modify the scatter scenario to take an option to scatter in 2-d or 3-d
  (already done via `dimensions` param, needs wiring to CLI)
- Modify the boids scenario to take an option to scatter in 2-d or 3-d
- Add a `--dimension` cli argument to entry.py to set 2 or 3d for those
  scenarios that accept it (defaults to 2, valid options 2 or 3)
- Keep everything minimally duplicative – DRY
- Refactor as necessary between 2-d and 3-d versions to keep visualization DRY
- Avoid modifications to law and solver code

## Approach

### `demo/src/teachgrav/visualisations/visualize.py`

1. Remove the `D != 2` guard in `visualize()`.
2. Add `_equal_3d_limits(mins, maxs, buffer)` → equal-aspect xlim/ylim/zlim.
3. Add `_apply_axis_style_3d(ax)` for minimal 3-D styling.
4. Add `_set_line_positions(line, positions, is_3d)` helper to DRY-up the
   identical update logic across `animate()` and `plot()`.
5. Rename internal 2D axes creation to `_axes_2d()`.
6. Add `_axes_3d()` that creates a `projection='3d'` subplot with equal-aspect
   limits and the same line-artist pattern as 2D.
7. `axes(trajectory, options, figsize)` dispatches to `_axes_2d` or `_axes_3d`
   based on `trajectory.D`.
8. `animate()` and `plot()` use `_set_line_positions()` – no dimension-specific
   branches outside that helper.

### `demo/src/teachgrav/scenarios/boids.py`

1. Add `dimensions: int = 2` parameter to `create()`.
2. Build position/velocity arrays as `n_boids × dimensions` by extending the
   existing x/y arrays with a z-component when `dimensions == 3`.
3. Raise `ValueError` for unsupported dimensions.

### `demo/src/teachgrav/entry.py`

1. Add `--dimension` argument: `type=int, default=2, choices=[2, 3]`.
2. In `execute_scenario()`: if `args.scenario in ('scatter', 'boids')`,
   include `dimensions=args.dimension` in `scenario_kwargs`.
3. In `_train_model()`: same injection for the training path.
4. In `_validate_args()`: if `args.dimension == 3` and
   `args.scenario not in ('scatter', 'boids')`, raise `ValueError`.

### Tests

- `test_viz.py`: 3D trajectory visualisation runs without error; `axes()`
  returns a 3D Axes object; `_set_line_positions` helper.
- `test_entry.py`: `--dimension 3` is accepted with scatter/boids; rejected
  with other scenarios; default is 2.
- `test_scenarios.py`: boids scenario with `dimensions=3` produces correct
  shape.
