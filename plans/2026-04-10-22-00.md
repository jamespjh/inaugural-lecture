# Plan: Improve Array Abstraction via Classes

**Date:** 2026-04-10  
**Issue:** Improve array abstraction via classes  
**Branch:** copilot/improve-array-abstraction-classes

## Goal

Refactor the monolithic `array_abstraction.py` (a single class with `if/elif` chains) into a proper class hierarchy:

- `BaseEngine` abstract base class
- One concrete subclass per engine variant
- Each engine (or closely-related group) in its own file
- A factory function using metaprogramming to map string engine names → class names
- All engine files moved into a `engines/` subfolder
- New tests that exercise the abstraction layer independently of scenarios

## Structure

```
demo/src/teachgrav/engines/
    __init__.py          # create_engine(name, seed) factory + all class imports
    base.py              # BaseEngine ABC + to_numpy_host helper
    numpy_engine.py      # NumpyEngine
    python_engine.py     # PythonEngine
    numba_engine.py      # NumbaEngine
    cupy_engine.py       # CupyEngine
    jax_engine.py        # JaxCpuEngine, JaxGpuEngine, JaxMetalEngine
    mlx_engine.py        # MlxCpuEngine, MlxGpuEngine
    torch_engine.py      # TorchCpuEngine, TorchGpuEngine, TorchMpsEngine
```

## Factory Pattern

`engine_name_to_class_name(name)` converts e.g. `'jax-cpu'` → `'JaxCpuEngine'` by
capitalising each hyphen-delimited segment and appending `'Engine'`.

`create_engine(name, seed=None)` uses this to look up the class in the module's
namespace and instantiate it.

## Backward Compatibility

- `array_abstraction.py` is kept but simplified: `ArrayAbstraction` becomes a thin
  factory wrapper calling `create_engine`, and `to_numpy_host` is re-exported.
- `engine_support.py` is left unchanged (detection logic, engine lists).

## Tests

New `demo/tests/teachgrav/test_array_abstraction.py` exercising:
- `engine_name_to_class_name` metaprogramming
- `create_engine` returns correct type
- `array()` round-trip for available engines
- `random_array()` shape and range for available engines
- `to_numpy_host()` helper
