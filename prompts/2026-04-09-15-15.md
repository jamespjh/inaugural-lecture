# Prompt: Issue #6 — Refactor demo code so fit training is independent of running a simulation with a fit

## User Instruction Summary

Implement the requirements from GitHub issue #6 in the `jamespjh/inaugural-lecture` repository:

- New entry CLI point for training — pass scenario to be used with different seeds to generate training data
- Save the parameters to the fit in an appropriate file — for the simple parametric fit (PLModel), a YAML file; for the GP (GPModel), a format appropriate to sklearn
- When using a trained law, new command line parameter `--model-data` pointing to the fit file — error out if not present and one of these laws is used
- No longer always retrain when the law is invoked

## Key Decisions and Reasoning

### Model serialisation formats

- **PLModel (power law)**: Only two scalar parameters (`G`, `power`). YAML is the natural choice — it's human-readable, easy to inspect, and trivially versioned. Used `yaml.dump` / `yaml.safe_load`.
- **GPModel (Gaussian process)**: A fitted sklearn `GaussianProcessRegressor` plus four normalisation arrays. Used `joblib.dump` / `joblib.load` since this is the sklearn-recommended format. The state dict bundles the fitted model and norms so loading is self-contained.

### Error-first design for fitted laws

`create_law()` now requires `model_data` for `gaussian` and `power`. If absent, it raises `ValueError` with a message telling the user to use `--model-data` and `train-model`. This is better than silently retraining because:
1. Training is expensive and would happen on every invocation.
2. Training results are stochastic — reproducibility requires a saved model.
3. Separation of concerns: the run command should not be responsible for training.

### New `train-model` CLI entry point

The `train.py` module provides a `train_model()` function registered as the `train-model` script. It accepts:
- `--law` (required): `gaussian` or `power`
- `--output` (required): path to save the model
- `--scenario`: training data scenario (default: scatter)
- `--n-systems`: number of random systems (default: 256)
- `--n-bodies`: bodies per system for scatter scenario (default: 3)
- `--seed`: numpy random seed for reproducibility
- `--engine`, `--log-level`, `--log-file`: as in main CLI

### Propagation of `model_data`

The `model_data` parameter was threaded through: `entry.parse_args()` → `entry.execute_scenario()` → `entry.solve()` → `integrator.integrate_trajectory()` → `laws.create_law()`. The `getattr` guard in `execute_scenario` ensures backward compatibility when `Args` objects are constructed manually in tests (e.g., `test_benchmark_mode_passes_law_and_timing`).

### Testing approach

- `test_model_persistence.py`: round-trip save/load for PLModel and GPModel; `create_law()` error behaviour; `create_law()` success with `model_data`; gravity law unaffected.
- `test_train.py`: full CLI tests for `train-model` — power saves YAML, gaussian saves joblib, seed is accepted.
- `test_entry.py`: added two tests for `--model-data` argument parsing.
