# Prompt Record: --n-bodies CLI parameter for scatter scenario

## Date
2026-04-09

## Issue
GitHub issue: "Make the number of bodies for the scatter scenario be specifiable as a command line parameter"

## Summary of User Instruction
Add a `--n-bodies` command-line parameter so users can control how many bodies are created in the `scatter` simulation scenario. The parameter should error out when used with scenarios that have a fixed number of bodies (moon, sun, single).

## Changes Made

### `demo/src/teachgrav/entry.py`
- Added `--n-bodies` argument (integer, default `None`) to `parse_args()`
- Added validation that raises `ValueError` if `--n-bodies` is given with any non-scatter scenario
- Updated `execute_scenario` to pass `n_bodies` as a kwarg to `create_scenario` when set
- Extracted `_resolve_output_format(args)` helper to keep `parse_args` within McCabe complexity limit of 10

### `demo/tests/teachgrav/test_entry.py`
- Added `test_n_bodies_scatter`: verifies `--n-bodies 6` is parsed correctly
- Added `test_n_bodies_default_is_none`: verifies default is `None`
- Added `test_n_bodies_non_scatter_raises`: parametrized over moon/sun/single, verifies `ValueError` is raised
- Added `n_bodies = None` to the `Args` stub in `test_benchmark_mode_passes_law_and_timing`

## Key Decisions

1. **Default value of `None`**: Using `None` rather than a magic default number allows us to distinguish "user didn't specify" from "user specified a number", so we don't inadvertently override `init_random_scatter`'s own default of 4.

2. **Validation in `parse_args`**: The check is placed in `parse_args` (not `execute_scenario`) so it follows the same pattern as other argument validation (e.g. `--duration` without `--video`).

3. **Passing via kwargs**: In `execute_scenario`, we only pass `n_bodies` if it's not `None`, so `scatter` still uses its own default (4) if `--n-bodies` is not given.

4. **Complexity refactor**: Adding the n_bodies validation pushed `parse_args` over the max-complexity=10 flake8 limit. Extracted `_resolve_output_format` helper to bring it back to 8, well within limits.
