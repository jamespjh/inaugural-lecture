# Prompt: 2026-04-15-17-28 — Equal-aspect orbit plot scaling

## User Instruction

> The distance scaling for plots of orbits should always be 1:1.
> At the moment the x and y axes can have different scales in internal units
> per pixel.  This is wrong - circles should be circles.
> The choice should be to take whichever range of distances is larger and use
> that.

## Key Decisions

### Helper function approach

Rather than calling `ax.set_aspect('equal')` (which interacts poorly with the
custom zero-crossing spine positioning in `_apply_axis_style`), the fix
computes equal-span axis limits explicitly.  This keeps full control over what
appears on screen without fighting matplotlib's layout engine.

A private helper `_equal_aspect_limits(mins, maxs, buffer)` was added to
`visualize.py` and imported into `convergence.py`, avoiding code duplication.

### Test strategy

Because `integrate_trajectory` requires `numba` (not available in the sandbox
environment), the `test_axes_equal_aspect_ratio` end-to-end test constructs a
minimal `Trajectory` directly from numpy arrays, bypassing the integrator
entirely.  This matches the pre-existing unit test style for the viz module.

### Scope

Only trajectory-orbit visualisations were changed (`visualize.axes()` and
`convergence.convergence_video()`).  Benchmark and GP plots were left
untouched because they intentionally use different scales on each axis.

## Summary of Reasoning

The root cause was two independent `set_xlim` / `set_ylim` calls using
per-axis min/max values.  By finding the larger data range and centering each
axis on its own midpoint using that range, both axes end up with identical
pixel-per-unit ratios without any matplotlib layout interaction.
