# Prompt Summary: Modify --benchmark to run single law step

**Date**: 2026-04-10

## User Instruction

Implement changes so that the `--benchmark` CLI switch, instead of running the whole simulation,
runs just a single step of the law with the scenario specified.

## Context from Issue

The issue (#33) states:
> "The benchmark switch, instead of running the whole sim, should just run one step of the law"

This was one of several sub-tasks in `tasks.md` under the "Benchmark figure" section.
Issue: https://github.com/jamespjh/inaugural-lecture/issues/33

## Investigation

1. Used `search_code_subagent` to locate the benchmark-related code in `entry.py` and tests.
2. Found that the existing benchmark block called `solve(system, args.method, law=args.law, factory=factory, dt=0.01, until=0.05)`, which integrates over a short time window.
3. The issue asks that only `model.law(system)` is called — a single evaluation of the physics law / acceleration model, with no ODE integration.
4. The `create_law` factory function exists in `laws/laws.py` and returns a `Model` object with a `.law(system)` method.

## Key Decisions

- **Import `create_law` at module level** in `entry.py` rather than inside the function, consistent with other imports in the file.
- **Keep the `factory` argument** when creating the law model so that fitted laws (Gaussian, Power) can be trained before benchmarking.
- **Update the print message** from "with method: ..." to "with law: ..." because benchmark mode no longer exercises the integration method at all.
- **Added a new test** (`test_benchmark_mode_runs_single_law_step_not_full_solve`) that patches both `create_law` and `solve` to verify exactly one law call and zero solve calls.
- **Existing test** (`test_benchmark_mode_passes_law_and_timing`) was kept unchanged since its assertions about how `benchmark_engine` is called remain valid.
