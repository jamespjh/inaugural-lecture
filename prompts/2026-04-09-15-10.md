# Prompt: Improve handling of stochastic test failures

**Issue:** Improve handling of tests that might stochastically fail

## User instruction summary

Add a decorator to mark tests that might stochastically fail so that they are rerun before being considered a failure. The decorator should take the number of reruns as a parameter (defaulting to 2). Use an existing pytest library if available, otherwise create a custom decorator. Go through all tests and mark those using `allclose` or otherwise likely to be stochastic.

## Key decisions and reasoning

### Using `pytest-rerunfailures`

`pytest-rerunfailures` is the standard pytest-ecosystem plugin for this use case. It provides `@pytest.mark.flaky(reruns=N)`, which reruns a test up to N times on failure before declaring it failed. This is preferable to writing a custom decorator because:
- It is well maintained and widely used
- It integrates cleanly with pytest's internals (e.g., handles `xfail`, parametrize, etc.)
- It requires no custom implementation or maintenance

The plugin was checked against the GitHub Advisory Database — no vulnerabilities found at version 16.1 (latest at time of writing).

### Which tests to mark

The tests were evaluated based on whether failure could plausibly be non-deterministic:

**Marked as flaky:**
- `test_gp_law_vectorised` — trains a GP model then checks vectorised law matches individual calls via `allclose`. ML training is stochastic.
- `test_normalise_denormalise` — uses randomly-generated arrays and `allclose`. Floating-point edge cases could theoretically arise.
- `test_pl_predict` — trains a PL model and checks prediction accuracy vs. true law with `allclose(atol=0.01)`. Training convergence may vary.
- `test_pl_law_vectorised` — trains a PL model then checks vectorised law matches individual calls via `allclose`. ML training is stochastic.
- `test_close_to_start_after_one_orbit` — runs numerical ODE integration for a full orbit and asserts the endpoint is close to the start (`allclose(atol=0.02)`). Integration accuracy can vary with numerical precision.

**Not marked (deterministic):**
- `test_constant_law_*` — no random data, purely deterministic computations.
- `test_create_scenario_single_*`, `test_same_seed_*` — fixed seeds or fixed inputs, deterministic.
- `test_law_vectorised` in `test_laws.py` — compares the true law called two ways; no stochasticity.
- `test_constant_single_body_moves_at_expected_position` — deterministic Euler/Tsit5 integration with known exact solution.

### Number of reruns

All marked tests use `reruns=2` (matching the default suggested in the issue).
