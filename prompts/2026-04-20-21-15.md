# Prompt Summary: Add Three-D Visualisation

## User instruction

Implement the "Add three-D visualisation" GitHub issue for the teachgrav
repository. The requirements were:

- Add visualization code with 3-d axes
- Modify the scatter scenario to take an option to scatter in 2-d or 3-d
- Modify the boids scenario to take an option to scatter in 2-d or 3-d
- Add a `--dimension` cli argument to entry.py (defaults to 2, valid options
  2 or 3)
- Keep everything minimally duplicative – DRY
- Refactor as necessary between 2-d and 3-d versions
- Avoid modifications to law and solver code

## Key decisions and reasoning

### No law/solver modifications required
The boids law (`boids_law.py`) already operates on arbitrary D-dimensional
data using vectorised numpy operations over the last axis. The gravity law
similarly works on any number of dimensions. No changes were needed.

### Scatter scenario already had `dimensions` parameter
`ScatterScenario.create()` already accepted `dimensions: int = 2`. The only
work needed was wiring this via the CLI `--dimension` argument.

### DRY refactoring in visualize.py
The key approach was:
1. Extract `_axes_2d()` (renamed from the monolithic `axes()`)
2. Add `_axes_3d()` using `mpl_toolkits.mplot3d`
3. Make `axes()` a dispatcher based on `trajectory.D`
4. Add `_set_line_positions(line, positions, is_3d)` helper to eliminate
   the duplicate update logic that would otherwise appear in both `animate()`
   and `plot()`
5. Add `_equal_3d_limits()` to compute equal-aspect limits in 3D space
6. Add `_apply_axis_style_3d()` for the pane/grid styling unique to 3D axes
7. Remove the `D != 2` guard in `visualize()` – it now supports any D

### 3D matplotlib approach
- Used `fig.add_subplot(111, projection='3d')` via mpl_toolkits.mplot3d
- 3D line artists require `line.set_data(x, y)` + `line.set_3d_properties(z)`
  rather than `line.set_data(*positions.T)`, hence the `_set_line_positions`
  helper
- `ax.set_xlim3d/ylim3d/zlim3d` for equal-aspect 3D axis limits

### Boids 3D initialisation
Extended `BoidsScenario.create()` to accept `dimensions: int = 2`. For 3D, a
z-position range of [-50, 50] and z-velocity range of [-5, 5] were chosen,
matching the relative scale of the existing y-velocity range.

### CLI design
- `--dimension` takes integer 2 or 3 (argparse `choices=[2, 3]`), defaults
  to 2
- Validation in `_validate_args()` raises a clear `ValueError` if
  `--dimension 3` is used with scenarios that don't support it (moon, sun,
  single)
- `dimensions=args.dimension` is injected into `scenario_kwargs` for both
  `scatter` and `boids` in all three code paths: `execute_scenario()`,
  `_train_model()`, and `benchmark_scenario()`
