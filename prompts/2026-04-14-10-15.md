# Prompt Summary: Engine-Consistent Seed Feature

## User Instruction

Enable scenario benchmarking sweeps that are consistent for the same RNG seed
across different engines.  The seed code was not consistent for the same
positions and velocities between engines.  The fix should work by:

* A flag `--engine-consistent-seed`, defaults to `True`.
* If set, scenario generation proceeds by generating using the NUMPY engine
  and then converting the data to the requested engine, rather than creating
  in that engine directly.

## Context and Exploration

### Problem

Different array backends (numpy, JAX, MLX, etc.) use different random number
generator implementations, so the same integer seed produces different random
values in each engine.  When benchmarking across engines, this means each
engine was starting from different initial conditions even for the same seed,
making cross-engine comparisons unfair.

### Relevant Code Areas

* `demo/src/teachgrav/engines/`: Per-backend engine classes (`NumpyEngine`,
  `JaxBaseEngine`, `MlxCpuEngine`, etc.) each have their own `seed_random` and
  `random_array` implementations.
* `demo/src/teachgrav/scenarios/__init__.py`: `ScenarioFactory` wraps an engine
  and creates scenario systems.
* `demo/src/teachgrav/entry.py`: CLI entry point, `parse_args`, `execute_scenario`,
  and `benchmark_scenario` functions.
* Pre-existing issue: `entry.py` contained three identical copies of
  `_validate_args` and two identical copies of `benchmark_scenario` (dead code
  from prior editing errors).  Python uses the last definition.

### Key Decisions

1. **Where to implement the logic**: In `ScenarioFactory.create_scenario` rather
   than at the engine level.  This keeps the conversion logic in one place and
   doesn't require modifying each engine class.

2. **Implementation strategy**: When `engine_consistent_seed=True` and a seed is
   provided and the target engine is not already numpy, instantiate a temporary
   `NumpyEngine` with the same seed, generate the scenario with it, then convert
   `data`, `masses`, and `immobile` arrays to the target engine via
   `to_numpy_host` + `engine.array()`.

3. **Default value**: `True` (enabled by default) so that benchmark sweeps are
   automatically consistent out of the box.

4. **Scope**: The flag has no observable effect when the engine is already numpy
   (no conversion needed) or when no seed is provided (unseeded randomness is
   inherently non-reproducible between runs).

5. **CLI flag style**: Used `argparse.BooleanOptionalAction` to support both
   `--engine-consistent-seed` and `--no-engine-consistent-seed` patterns.

6. **YAML batch configs**: The existing `_config_to_force_args` in `generate.py`
   handles boolean flags as "include flag or not" (only adds the flag when True).
   Since the default is True, YAML users can only explicitly enable the flag, not
   disable it through YAML.  This is an acceptable limitation for the scope of
   this issue; disabling it via YAML would require `_config_to_force_args`
   to emit `--no-engine-consistent-seed` for False booleans.

7. **Test stubs**: The `Args` stub classes in `test_entry.py` (used for
   `execute_scenario` unit tests) required adding `engine_consistent_seed = True`
   to avoid `AttributeError`.

## Changes Made

1. **`demo/src/teachgrav/scenarios/__init__.py`**:
   - Added `to_numpy_host` import.
   - Added `engine_consistent_seed=True`, `_engine_name`, `_seed`,
     `_engine_consistent_seed` to `ScenarioFactory.__init__`.
   - Added conditional logic in `create_scenario` to generate via numpy and
     convert arrays when `engine_consistent_seed=True` and target engine is not
     numpy.

2. **`demo/src/teachgrav/entry.py`**:
   - Added `--engine-consistent-seed` / `--no-engine-consistent-seed` argument
     to `parse_args` (default `True`).
   - Updated all three `ScenarioFactory(...)` instantiations to pass
     `engine_consistent_seed`.

3. **`demo/tests/teachgrav/test_entry.py`**:
   - Added `engine_consistent_seed = True` to both `Args` stub classes.
   - Added `test_engine_consistent_seed_default_is_true`.
   - Added `test_no_engine_consistent_seed`.

4. **`demo/tests/teachgrav/test_scenarios.py`**:
   - Added `numpy` and `to_numpy_host` imports.
   - Added `test_engine_consistent_seed_matches_numpy` parametrized test
     verifying that `engine_consistent_seed=True` makes all engines produce
     the same initial conditions as numpy for the same seed.
