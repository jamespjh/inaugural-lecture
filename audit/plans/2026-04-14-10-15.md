# Plan: Enable Engine-Consistent Seed for Scenario Benchmarking

## Problem

Different array backends (numpy, JAX, MLX, etc.) use different RNG
implementations, so the same integer seed produces different random
values in each engine.  When sweeping benchmark scenarios across
engines, the initial conditions (positions, velocities, masses) differ
between engines even for the same seed, making cross-engine comparisons
unfair.

## Solution

Add an `--engine-consistent-seed` flag (default: `True`) that forces
scenario generation to use the numpy engine and then converts the
resulting arrays to the requested engine.  This guarantees that any
engine receives the same initial conditions for the same seed.

## Steps

1. **`demo/src/teachgrav/scenarios/__init__.py`** – extend
   `ScenarioFactory`:
   - Add `engine_consistent_seed=True` parameter to `__init__`.
   - In `create_scenario`, when `engine_consistent_seed=True`,
     `seed is not None`, and the engine is not already numpy:
     * Create a temporary `NumpyEngine` with the same seed.
     * Generate the scenario with that numpy engine.
     * Convert `data`, `masses`, and `immobile` arrays to the target
       engine via `to_numpy_host` + `engine.array()`.
     * Return the converted `System`.

2. **`demo/src/teachgrav/entry.py`** – CLI flag:
   - Add `--engine-consistent-seed` / `--no-engine-consistent-seed`
     (`BooleanOptionalAction`, default `True`) to `parse_args`.
   - Pass `engine_consistent_seed=args.engine_consistent_seed` to
     `ScenarioFactory` in both `execute_scenario` and
     `benchmark_scenario`.

3. **`demo/tests/teachgrav/test_entry.py`** – update stubs and add tests:
   - Add `engine_consistent_seed = True` to the `Args` stub classes
     used in `execute_scenario` tests.
   - Add two new tests:
     * `test_engine_consistent_seed_default_is_true`
     * `test_no_engine_consistent_seed`

4. **`demo/tests/teachgrav/test_scenarios.py`** – add cross-engine test:
   - `test_cross_engine_consistency_with_engine_consistent_seed`:
     same seed + `engine_consistent_seed=True` → identical scatter to
     numpy engine.

## Key Decisions

- Default is `True` so benchmarks are consistent out of the box.
- The flag has no effect when the engine is already numpy, or when no
  seed is supplied (unseeded randomness is inherently non-reproducible
  between runs).
- All three arrays (`data`, `masses`, `immobile`) are converted so the
  `System` is fully native to the target engine.
