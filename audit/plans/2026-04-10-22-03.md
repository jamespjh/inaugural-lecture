# Plan: Generate tables of benchmarking data (Issue #N)

## Summary

Add `--benchmark` mode to the `generate-figures` CLI entry point so that users
can sweep over parameter arrays defined in the input YAML and receive CSV
benchmark-timing tables on stdout or in a file.

## Requirements (from issue)

- `--benchmark` switch on the `generate-figures` entry point
- Ignores viz switches – warns if they are given
- Outputs to stdout or file (warns if output file does not end in `.csv`)
- Outputs CSV
- Input YAML is the usual set of data, but if an array is given for any
  parameter, we run for each value
- Results are composed into a table
- Max of two array parameters: first → column axis, second → row axis
- Special marker: if an array is given in `[start:stop:step]` format it is
  converted first
- If multiple scenarios are given, those form the first axis with a special
  `key` field to use as the column label

## Design

### Table structure

| Case | Columns | Rows |
|------|---------|------|
| 1 scenario, 1 array param | `[param, time]` | one row per param value |
| 1 scenario, 2 array params | first-param values | second-param values |
| N scenarios (with `key`) | scenario keys | first array param values |

### `[start:stop:step]` notation

A YAML string matching `[start:stop:step]` is expanded via `numpy.arange`
before parameter expansion.  Integer-valued lists are converted from `float`
to `int` for display clarity.
