# Plan: Issue #8 — Videos of trajectories as a fitted law converges

Date: 2026-04-13 14:05

## Goal

Generate a video showing the power-law model trajectory converging toward the
true inverse-square law as the optimiser iterates, and hook it into slide 3.1.2
of the lecture.

## Requirements

From the issue and comments:

1. As we train a fitted-law against scatter scenarios, capture model parameters
   at successive steps of the training loop.
2. For each checkpoint, simulate the same scenario and visualise its trajectory
   as a still trail.
3. Combine those still-trail frames into a video showing the trajectory
   converging toward the final fitted law.
4. Optionally overlay the true-law trajectory in a different colour per frame.
5. Add as visualisation options when running with `--train` (the existing
   error message blocking `--train --outfile` stays; a new dedicated
   `--convergence-video` argument is added instead).
6. Hook the resulting video into slide 3.1.2 ("Physics-free gravity").

## Design Decisions

### Checkpoint collection during training

`scipy.optimize.minimize` accepts a `callback` parameter called once per
optimisation iteration (not once per objective evaluation). We add this
callback to `PLModel.train()` and return the collected checkpoints as a list.

An optional `on_step` callable can be passed in by the caller (used in tests
and potentially by a future interactive use).

### Stability filtering

Early-training parameters (e.g. large or negative G/power values) can produce
numerically unstable trajectories (Inf/NaN). The `_generate_convergence_video`
function silently skips such trajectories rather than failing. The
`convergence_video` viz function also uses `np.isfinite` when computing axis
bounds as a safety net.

### Visualization approach

A new `convergence_video()` function in `viz.py` uses `matplotlib.animation
.FuncAnimation` + `FFMpegWriter`, consistent with the existing `animate()`
function. Each "frame" in the FuncAnimation corresponds to a different
training checkpoint (not a different time step within a single simulation).

The reference (true-law) trajectory, when requested, is pre-computed once and
overlaid on every frame in `dodgerblue` dashed lines. The fitted trajectories
are drawn in `lemonchiffon`.

### Axis bounds

Global axis limits are computed from the union of all finite positions across
all trajectories + the optional reference. A 1.0-unit buffer is added. If no
finite positions exist (all trajectories blew up), a fallback [-10, 10] range
is used.

### CLI integration

New arguments (only meaningful with `--train --law power`):

| Argument | Default | Description |
|---|---|---|
| `--convergence-video PATH` | None | Output `.mp4` file for the convergence video |
| `--checkpoint-interval N` | 1 | Use every Nth checkpoint as a frame |
| `--show-true-law` | False | Overlay the gravity (true) law trajectory |

The existing `--train --outfile` / `--train --video` rejection is preserved to
avoid ambiguity. `--convergence-video` is the dedicated path.

The `_validate_args` complexity was reduced by extracting `_validate_train_args`
as a separate helper.

### Slide integration

Slide 3.1.2 ("Physics-free gravity") in `slideshow/part3.qmd` now references
`assets/power_law_convergence.mp4` via the existing `video-credit` shortcode.

A generation command is documented as a comment in `slideshow/assets/scenarios.yml`.

### integrate_trajectory extension

`integrate_trajectory()` in `integrator.py` gains an optional `model` keyword
argument. When provided, the law-name/factory/model-data arguments are ignored
and the supplied model object is used directly. This allows
`_generate_convergence_video` to pass checkpoint PLModel instances without
writing temporary YAML files.

## Generating the video

```bash
cd demo && source venv/bin/activate
teachgrav --train --law power --scenario scatter \
          --model-data /tmp/model.yaml \
          --n-systems 256 --seed 42 \
          --convergence-video ../slideshow/assets/power_law_convergence.mp4 \
          --show-true-law
```
