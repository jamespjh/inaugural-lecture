# Plan: Issue — Orbit plot distance scaling should always be 1:1

## Problem

The x and y axes in orbit trajectory plots can have different scales (internal
units per pixel), making circular orbits appear elliptical.  The fix is to
always use the larger of the two data ranges for both axes, centred on each
axis's midpoint.

## Files Affected

- `demo/src/teachgrav/visualisations/visualize.py`
- `demo/src/teachgrav/visualisations/convergence.py`
- `demo/tests/teachgrav/test_viz.py`

## Changes

### 1. Add `_equal_aspect_limits()` helper in `visualize.py`

New private function placed before `_apply_axis_style`.  Given `mins`, `maxs`,
and a `buffer`, it:

1. Computes the midpoint of each axis.
2. Takes the larger half-range across x and y.
3. Returns symmetric `(lo, hi)` tuples for each axis.

### 2. Update `axes()` in `visualize.py`

Replace the independent `set_xlim`/`set_ylim` calls with calls through
`_equal_aspect_limits`.

### 3. Update `convergence_video()` in `convergence.py`

Import `_equal_aspect_limits` and apply it in the same way.

### 4. Add tests in `test_viz.py`

- `test_equal_aspect_limits_square_data` – equal ranges → limits unchanged.
- `test_equal_aspect_limits_wide_data`   – x wider → y expanded to match.
- `test_equal_aspect_limits_tall_data`   – y taller → x expanded to match.
- `test_equal_aspect_limits_buffer`      – buffer is applied after equalising.
- `test_axes_equal_aspect_ratio`         – end-to-end check that `axes()`
  produces equal x and y spans for an asymmetric trajectory.

## Non-goals

- Not changing `ax.set_aspect('equal')` (that would conflict with the custom
  spine positioning in `_apply_axis_style`).
- Not touching benchmark or GP plots which intentionally use independent axes.
