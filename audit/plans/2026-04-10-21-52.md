# Plan: Modify --benchmark switch to run single law step

**Date**: 2026-04-10

## Issue

The `--benchmark` CLI switch currently runs the full simulation (calling `solve()` with a
short `until=0.05` window). The issue asks it to instead run just **a single step of the law**
(i.e. one call to `model.law(system)`), which measures the cost of evaluating the physics
law/acceleration model rather than the whole ODE integration loop.

## Changes

### `demo/src/teachgrav/entry.py`

1. Add `create_law` to the imports from `.laws.laws`.
2. In the `execute_scenario` function, replace the benchmark block:
   - **Before**: creates a `run_once` closure that calls `solve(...)` with a small `until=0.05`
   - **After**: creates the law model with `create_law(args.law, factory=factory)`, then a
     `run_once` closure that calls `model.law(system)` — a single evaluation of the law.
3. Update the print message from `"with method: {args.method}"` to `"with law: {args.law}"`,
   since we're now benchmarking the law, not the integration method.

### `demo/tests/teachgrav/test_entry.py`

1. Existing test `test_benchmark_mode_passes_law_and_timing` is unchanged in its assertions;
   it still verifies that `benchmark_engine` is called with the right engine and that `fn()` is
   callable — this remains valid.
2. New test `test_benchmark_mode_runs_single_law_step_not_full_solve` added to explicitly verify:
   - `model.law()` is called exactly once during benchmarking
   - `solve()` is **not** called at all

## Rationale

Benchmarking a single law step is the correct measurement for comparing the performance of
different physics laws and computation engines. The full solve includes integration overhead
that obscures the law performance. This aligns with the task description in `tasks.md`:
> "Make a new CLI entry point to run a benchmark over the range of engines and model sizes"
> "Modify the --benchmark switch to just run a single step of the law with the scenario specified"
