# Plan: Make python/numba law work with standard scenarios (PR review response)

Date: 2026-04-14

## Context

PR review feedback on #37 (copilot/implement-gravity-law-pure-python):
- The python law should work with all the standard scenarios
- When the python law is called with input data from a scenario created using
  a different engine, we need to convert internally
- Create scenarios for the python engine using the numpy factory then convert
  in the law, rather than rewriting scenario code to work with python arrays
- Continue to use parametrized tests, expanding the engine list to include
  python and numba

## Problem with Previous Approach

The previous commit added 4 hand-crafted tests that used raw Python lists
(`_moon_flat_data`) passed directly to `flat_law`. This tested the internal
helper function but not the actual scenario → law workflow.

The reviewer's concern (comment on line 79) was that the python law should
work with standard scenarios (moon, sun, scatter) not just with hand-crafted
data.

The previous `law()` and `flat_law()` methods did not convert their inputs
from numpy/JAX arrays to Python lists, so calling them with a numpy system
would fail for the python engine.

## Changes Made

### 1. `demo/src/teachgrav/laws/true_law.py`

- Added `import numpy as np` and `from ..array_abstraction import to_numpy_host`
- Added `_to_py_list(array_like)` static helper to convert any backend array
  to a Python list (wraps `to_numpy_host(np.asarray(...)).ravel().tolist()`)
- Added `law(system)` override for python engine: converts system data from
  any backend (numpy, JAX, etc.) to Python lists before computing, returns
  numpy array with same shape
- Updated `flat_law` to convert inputs using `_to_py_list()` before calling
  `_python_gravity_flat_law()`, and wrap result as numpy array
- Removed the "1-D only" doc note (not enforced, not necessary to document)

### 2. `demo/tests/teachgrav/test_laws.py`

- Removed the 4 hand-crafted python-engine tests and `_moon_flat_data` helper
- Removed `import numpy as np` (no longer needed)
- Added `from teachgrav.engine_support import get_available_engines`
- Added `ENGINES_WITH_PYTHON_LAW` list = numpy engines + python + numba (if
  available)
- Updated `test_law_scatter_3D` to use `ENGINES_WITH_PYTHON_LAW` and create
  scenarios with numpy for python-like engines
- Kept `test_law_vectorised` with `ENGINES_TO_TEST` only (vectorised batch
  calling is a numpy/JAX feature, not supported for python engine)
- Renamed `system_engine` → `scenario_engine` for clarity
