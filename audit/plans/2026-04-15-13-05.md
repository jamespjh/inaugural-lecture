# Plan: Unified FPS control for video paths (Steps 1-5)

## Date: 2026-04-15

## Context

This change implements the first phase of the previously agreed plan to unify video frame-rate controls across teachgrav outputs. The objective for this commit is restricted to plan steps 1-5: argument plumbing and call-path wiring only.

## Full Plan (authoritative)

Add a single global `--fps` CLI option (default 20) and thread it through both normal animation and convergence-video rendering. For convergence videos, ensure output frame count targets `duration * fps`; when selected checkpoints are fewer than the target, synthesize intermediate parameter states between checkpoints and run additional trajectory solves so playback has the requested temporal density.

**Steps**
1. Phase 1: CLI and argument plumbing.
2. Add `--fps` to `parse_args()` in `/Users/jamespjh/devel/inaugural/demo/src/teachgrav/entry.py` with default 20 and help text clarifying it applies to all video outputs.
3. Remove fallback use of `convergence_fps` in `_generate_convergence_video()` and route `args.fps` into convergence rendering.
4. Route `args.fps` into standard simulation visualization by updating `execute_scenario()` call to `visualize(...)` and extending `visualize()`/`animate()` signatures in `/Users/jamespjh/devel/inaugural/demo/src/teachgrav/viz.py`.
5. Phase 2: Convergence target-frame planning and interpolation logic.
6. In `_generate_convergence_video()`, compute `target_frames = max(1, int(args.duration * args.fps))` after checkpoint interval filtering.
7. Keep existing checkpoint filtering and instability skipping behavior as the base path; treat surviving checkpoint parameter states as keyframes.
8. If surviving keyframes are already `>= target_frames`, downsample keyframes to exactly `target_frames` using index interpolation so playback duration still matches requested fps/duration.
9. If surviving keyframes are `< target_frames`, construct a dense parameter schedule of length `target_frames` by piecewise-linear interpolation across keyframe index space for both `G` and `power`, preserving first and last keyframe values exactly.
10. Integrate one trajectory per scheduled parameter pair (including interpolated states) using existing `integrate_trajectory(..., method, dt, until)` pathway and current error-handling semantics (skip failed/non-finite integrations).
11. Add guardrails for pathological cases: if all generated frames fail, emit warning and skip video; if fewer than requested succeed, continue with available frames and log a warning that achieved frame count is below target.
12. Phase 3: Rendering and compatibility adjustments.
13. Update `convergence_video()` in `/Users/jamespjh/devel/inaugural/demo/src/teachgrav/viz.py` to keep fps as a caller-provided value (no behavior change beyond using unified caller input) and continue using `frames=len(trajectories)`.
14. Preserve existing bbox policy (reference trajectory first, then final fitted trajectory) and true-law overlay behavior unchanged.
15. Phase 4: Tests and regression coverage.
16. Update parse-args tests in `/Users/jamespjh/devel/inaugural/demo/tests/teachgrav/test_convergence_video.py` to assert `args.fps` default 20 and custom parsing.
17. Update convergence invocation tests to expect `fps=args.fps` instead of `convergence_fps` (adjust fake args classes accordingly).
18. Add targeted test for upsampling path: with few checkpoints and `duration * fps` larger than checkpoint count, assert convergence renderer receives expanded trajectory count (mock `integrate_trajectory` and `convergence_video`).
19. Add targeted test for no-upsample/downsample path: when checkpoints exceed target frames, assert renderer receives exactly `target_frames` trajectories.
20. Retain existing tests for solver flag forwarding, skip-failed checkpoint handling, and true-law overlay, adjusting only expectations affected by fps unification.
21. Phase 5: Verification.
22. Run focused tests: `demo/tests/teachgrav/test_convergence_video.py` and `demo/tests/teachgrav/test_viz.py`.
23. Run at least one CLI smoke check for non-training video path to confirm `--fps` affects standard animation duration/frame pacing.
24. Run manual convergence smoke command with low checkpoint count and larger `duration*fps` to confirm interpolation-based densification occurs and output is produced.
