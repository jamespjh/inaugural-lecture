# Plan: Isolate visualization and convergence APIs from CLI args

## Date: 2026-04-15

## Context

The convergence video generation and general visualization logic were moved out of `entry.py` into a dedicated visualization module. After that move, one architectural issue remained: the parsed CLI namespace (`args`) still crossed the `entry.py` boundary into the external convergence generator. The goal of this step is to complete the boundary cleanup and establish a clearer module pattern.

## Objectives

1. Move the visualization implementation out of `viz.py` into a dedicated module under `visualisations/`.
2. Move convergence-video generation logic out of `entry.py` into the same visualization area.
3. Keep `viz.py` as a compatibility facade so existing imports continue to work.
4. Ensure parsed CLI state does not leave `entry.py`; external functions should receive explicit named parameters instead.
5. Update tests to patch the new implementation locations and verify the refactor.

## Changes

### `demo/src/teachgrav/visualisations/__init__.py` (new)
Create the package container for visualization-specific modules.

### `demo/src/teachgrav/visualisations/convergence.py` (new)
Move here:
- general visualization helpers (`visualize`, `animate`, `plot`, `axes`)
- convergence renderer (`convergence_video`)
- convergence generation orchestration (`generate_convergence_video`)

Refine `generate_convergence_video` so it accepts explicit parameters rather than a parsed CLI namespace:
- `checkpoints`
- `scenario`
- `output`
- `checkpoint_interval`
- `show_true_law`
- `seed`
- `method`
- `dt`
- `until`
- `duration`
- `fps`
- `scenario_kwargs`

### `demo/src/teachgrav/viz.py`
Convert to a compatibility re-export module that imports the visualization functions from `teachgrav.visualisations.convergence`.

### `demo/src/teachgrav/entry.py`
Keep a thin `_generate_convergence_video(args, checkpoints, scenario_kwargs)` wrapper inside `entry.py` that translates CLI namespace values into explicit arguments for `generate_convergence_video(...)`.

### Tests
Update patch targets and keep focused regression coverage passing:
- `demo/tests/teachgrav/test_convergence_video.py`
- `demo/tests/teachgrav/test_viz.py`

## Verification

- Run focused tests:
  - `./venv/bin/pytest tests/teachgrav/test_convergence_video.py tests/teachgrav/test_viz.py`
- Ensure `entry.py` no longer passes parsed `args` into external modules.
- Ensure compatibility imports through `teachgrav.viz` still work.

## Expected outcome

`entry.py` remains the only place that knows about the parsed CLI namespace, while visualization and convergence modules expose stable explicit APIs suitable for reuse and testing.
