# Plan: Improve handling of stochastic test failures

**Issue:** Add a mechanism to rerun tests that may fail stochastically (e.g., ML model training accuracy checks, numerical integration tolerance checks).

## Approach

Use the `pytest-rerunfailures` plugin (already available in the pytest ecosystem), which provides the `@pytest.mark.flaky(reruns=N)` decorator. This is the standard pytest-ecosystem solution for this problem.

## Changes

1. **`demo/pyproject.toml`** — Add `pytest-rerunfailures` to the `[dev]` optional dependencies.

2. **Mark stochastic tests** with `@pytest.mark.flaky(reruns=2)`:

   - `test_gp_law_vectorised` in `tests/teachgrav/test_gp.py`
     — Trains a GP model and uses `allclose` to compare vectorised vs individual calls.
   - `test_normalise_denormalise` in `tests/teachgrav/test_gp.py`
     — Uses random input data and `allclose` to check round-trip normalisation.
   - `test_pl_predict` in `tests/teachgrav/test_pl.py`
     — Trains a PL model and checks prediction accuracy against the true law with `allclose`.
   - `test_pl_law_vectorised` in `tests/teachgrav/test_pl.py`
     — Trains a PL model and uses `allclose` to compare vectorised vs individual calls.
   - `test_close_to_start_after_one_orbit` in `tests/teachgrav/test_integrator.py`
     — Runs numerical integration for a full orbit and checks final position is close to start with `allclose`.

## Rationale for test selection

Tests were selected if they either:
- Involve ML model training (GP/PL) which is inherently stochastic and may produce different numerical results on different runs.
- Use `allclose` comparisons in a context where accumulated floating-point or numerical integration errors could lead to intermittent failures.

Tests using `allclose` on purely deterministic computations (e.g., `test_constant_law_*`, `test_create_scenario_single_*`) were not marked, as they should always produce the same result.
