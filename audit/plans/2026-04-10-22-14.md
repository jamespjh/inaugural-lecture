# Plan: Pure-Python (numpy-free) Gravity Law

Date: 2026-04-10

## Issue

Issue #37 — "Pure-python (numpy-free) law"

> Our 'python' and 'numba' engines require a law for gravity which runs without numpy array syntax.
> In true-law, if self.factory is a pure-python or numba engine, don't call off to power law, but instead, do explicit-nested-for-loop implementation of gravity.

Comment from @jamespjh:
> Make sure the python code is really readable and pedagogical. This is not needed to be efficient.

## Analysis

`TrueLawModel` currently extends `PLModel` and defers entirely to `PLModel.flat_law()`, which
uses numpy vectorised array operations (`np.linalg.norm`, `np.where`, `np.sum`, `np.newaxis`, etc.).
These operations are not available when the engine is `'python'` (data is plain Python lists) or
`'numba'` (data is numba typed lists).

## Changes Planned

### 1. `demo/src/teachgrav/laws/true_law.py`

- Accept `factory=None` in `__init__` (passed to `PLModel.__init__`)
- Override `flat_law`:
  - If `self.factory.engine.engine` is `'python'` or `'numba'`: dispatch to for-loop implementation
  - Otherwise: delegate to `super().flat_law()` (PLModel's vectorised numpy version)
- Add `_python_gravity_flat_law(data, masses, immobile)`:
  - Parse flat data into positions and velocities using index arithmetic
  - Use explicit double for-loop over body pairs (pedagogically clear Newton's law)
  - Use `math.sqrt` and plain Python arithmetic only
  - Zero out immobile body derivatives
  - Return result as a flat Python list

### 2. `demo/src/teachgrav/laws/laws.py`

- Update `create_law` for `law_name == 'gravity'` to pass `factory` to `TrueLawModel(factory=factory)`

### 3. `demo/tests/teachgrav/test_laws.py`

- Add `test_python_engine_flat_law`: call `flat_law` directly with Python lists and verify output
- Add `test_python_engine_matches_numpy`: verify the python for-loop result matches the numpy result
  (using the moon-orbiting-Earth scenario as a known-correct reference)

## Out of Scope

- Making full end-to-end Euler integration work for `python` engine (that requires fixing arithmetic
  on `System` and `Change` objects with Python-list data, and is a separate concern)
- Numba JIT-compiled version (the for-loop implementation uses plain Python; numba may JIT it
  automatically in future if wrapped with `@numba.njit`)
