# Plan: Issue #6 — Refactor demo code so fit training is independent of running a simulation with a fit

## Goal

Decouple model training from simulation execution so that:
1. Fitted laws (`gaussian`, `power`) must be trained in a separate step before use
2. Trained models are saved to files and loaded on demand
3. A new `train-model` CLI entry point handles training
4. The `teachgrav` CLI accepts `--model-data` pointing to the saved file

## Acceptance Criteria (refined)

- [ ] `train-model --law power --output model.yaml --n-systems 256` trains and saves a YAML file with `G` and `power`
- [ ] `train-model --law gaussian --output model.joblib --n-systems 256` trains and saves a joblib file
- [ ] `teachgrav --law power --model-data model.yaml` loads the model and runs the simulation
- [ ] `teachgrav --law gaussian --model-data model.joblib` loads the model and runs the simulation
- [ ] `teachgrav --law power` (without `--model-data`) raises a clear error message
- [ ] `teachgrav --law gaussian` (without `--model-data`) raises a clear error message
- [ ] `create_law('power')` and `create_law('gaussian')` raise `ValueError` when `model_data` is `None`
- [ ] All existing tests pass

## Key Decisions

- PLModel: YAML is ideal since it has only two scalar parameters (G, power). Easy human-readable inspection.
- GPModel: joblib is the sklearn-recommended serialisation format. We save the fitted `GaussianProcessRegressor` plus the normalisation stats (X_mean, X_std, Y_mean, Y_std) as a dict.
- `create_law()` raises `ValueError` rather than silently retraining, providing a clear error message pointing to `--model-data` and `train-model`.
- `train-model` supports `--n-systems`, `--n-bodies`, `--seed`, `--scenario`, `--engine`, `--log-level`, `--log-file` for full flexibility.
- No changes to `constant` or `gravity` laws — they don't require training.
