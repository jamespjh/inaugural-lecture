# Prompt: Pure-Python (numpy-free) Gravity Law

Date: 2026-04-10

## User Instruction

> Our 'python' and 'numba' engines require a law for gravity which runs
> without numpy array syntax.
> In true-law, if self.factory is a pure-python or numba engine, don't call
> off to power law, but instead, do explicit-nested-for-loop implementation
> of gravity.
>
> Make sure the python code is really readable and pedagogical. This is not
> needed to be efficient.

## Analysis

### Why the old code didn't work for python/numba

`TrueLawModel` extended `PLModel` and had **no `factory` parameter** — it always
passed `factory=None` to the parent.  `PLModel.flat_law` uses full numpy
vectorised syntax (`np.linalg.norm`, `np.where`, `np.sum`, `np.newaxis`,
`data.__array_namespace__()`, etc.).  The `'python'` engine stores data as
nested Python lists (no `__array_namespace__`), and the `'numba'` engine stores
data as numba typed lists — neither supports numpy vectorised operations.

### Approach chosen

- Give `TrueLawModel.__init__` a `factory=None` parameter so callers (including
  `create_law`) can inject the factory.
- Override `flat_law` in `TrueLawModel`: if `self.factory.engine.engine` is in
  `{'python', 'numba'}`, dispatch to a new private method
  `_python_gravity_flat_law`; otherwise fall through to `super().flat_law()`.
- `_python_gravity_flat_law` uses **only plain Python and `math.sqrt`**:
  explicit double for-loop over body pairs, parsing the flat data list by index
  arithmetic, accumulating acceleration contributions, zeroing immobile bodies,
  then packing the result back into a flat Python list.
- Update `create_law` to pass `factory` to `TrueLawModel(factory=factory)`.

### What is out of scope

Full end-to-end Euler integration with the `'python'` engine requires `System`
and `Change` to support arithmetic on Python lists (the `System` class currently
uses `__array_namespace__()` which Python lists don't implement).  That is a
separate concern; the issue only asked for the law itself.

## Key Decisions

1. **Guard via `PYTHON_LIKE_ENGINES` set** — makes it easy to add other
   "plain Python" engine variants in the future.
2. **No new imports in the module body** — `math` is stdlib, always available.
3. **Pedagogical comments** — docstring explains Newton's law formula; inline
   comments name each step (parse, kinematics, pairwise gravity, immobile mask,
   repack).
4. **Works with numpy arrays too** — the for-loop implementation accepts any
   sequence (Python list, numpy array, numba typed list) since it only uses
   indexing and plain arithmetic.
5. **Tests call `flat_law` directly with Python lists** — avoids the need to
   fix `System`/`ScenarioFactory` for the python engine (out of scope) while
   still exercising the real code path.
