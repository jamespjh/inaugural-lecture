# Prompt Summary for Law Selection + Constant Motion Asset

## User request summary
The user asked to implement a law-selection pipeline in the teachgrav demo, add a constant-velocity law and single-particle scenario, enforce solver compatibility for fitted laws, add test coverage, generate the constant-motion movie, and wire it into slide 1.1.3. They also requested macOS pin compliance via pyproject and explicit demo venv executable usage for test runs in sandboxed contexts.

## What was implemented
- Added `--law` CLI support in `demo/src/teachgrav/entry.py` with values `gravity`, `constant`, `gaussian`, `power`.
- Added method normalization in argument parsing: fitted laws (`gaussian`, `power`) with non-Euler solvers emit warning and switch to `euler`.
- Threaded selected law through solve/integration calls.
- Added law factory in `demo/src/teachgrav/laws/laws.py`.
- Added new `ConstantLawModel` in `demo/src/teachgrav/laws/constant_law.py`.
- Added `single` scenario in `demo/src/teachgrav/scenarios.py` and fixed its shape to `(2, N, D)` for `N=1`.
- Updated integrator signature and model construction in `demo/src/teachgrav/integrator.py`.
- Added tests in:
  - `demo/tests/teachgrav/test_entry.py`
  - `demo/tests/teachgrav/test_integrator.py`
  - `demo/tests/teachgrav/test_scenarios.py`
  - `demo/tests/teachgrav/test_constant_law.py`
- Added slideshow asset config for constant motion in `slideshow/assets/scenarios.yml`.
- Updated video reference in `slideshow/part1.qmd` to `assets/constant_euler.mp4`.
- Generated `slideshow/assets/constant_euler.mp4` and verified rendered output references it.

## Key decisions and reasoning
1. Fitted-law solver handling used auto-normalization (warning + fallback) rather than hard failure to preserve smooth CLI UX while preventing incompatible combinations.
2. A dedicated `single` scenario was added to provide deterministic constant-motion behavior and a reliable slide asset source.
3. Tests were expanded to cover parser behavior, fallback behavior, constant law derivatives, immobile masking, and straight-line position expectation.
4. On macOS in this environment, dependency installation was enforced from pyproject to honor the Darwin pin (`diffrax==0.7.2`).
5. Test execution used explicit demo-venv pytest paths; `JAX_PLATFORMS=cpu` was applied where needed to avoid Metal backend aborts during sandboxed runs.

- Quarto render succeeded (unsandboxed due architecture detection restrictions), and rendered HTML referenced `assets/constant_euler.mp4`.
