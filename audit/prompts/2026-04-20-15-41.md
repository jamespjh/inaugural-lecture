# Prompt Summary: CuPy Test Failures in Array Namespace and Conversion

## Original Request
Investigate and fix CuPy failures on a CUDA-capable machine for two error families:
- `AttributeError: 'ndarray' object has no attribute '__array_namespace__'`
- `TypeError: Implicit conversion to a NumPy array is not allowed. Please use .get()`

## Investigation and Findings
1. Reproduced both failure families in the demo virtual environment using CuPy tests
2. Confirmed runtime behavior of CuPy 14:
   - `cupy.ndarray` does not provide `__array_namespace__` in this environment
   - CuPy disallows implicit `np.asarray` conversion and expects explicit host copy
3. Traces showed failures in law implementations using `.__array_namespace__()` and in `to_numpy_host` fallback logic

## Implementation Approach
1. Added a CuPy-specific array API compatibility patch in `CupyEngine._setup`:
   - Introduce `_ensure_cupy_array_api(cp)`
   - Monkeypatch `cp.ndarray.__array_namespace__` if missing
   - Guard with `_teachgrav_array_api_patched` to avoid repeated patching
2. Updated `to_numpy_host` in `engines/base.py`:
   - Keep existing `detach/cpu/numpy` handling
   - Add `.get()` handling before falling back to `np.asarray`

## Key Decisions
- Keep fixes centralized in engine compatibility and host-conversion helpers
- Avoid touching each law model call site individually
- Follow existing Torch compatibility pattern for consistency
