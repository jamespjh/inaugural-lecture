## Key Decisions and Reasoning

1. **Use `generate-figures --benchmark` CLI** – the existing entry point in
   `generate.py` already supports multi-scenario YAML sweeps that produce a CSV.
   The benchmark YAML uses the multi-scenario format: one config per engine
   (labeled by `key`), each with an `n-bodies` list for the row sweep.

2. **Separate `plot-benchmark` entry point** – `generate-figures --benchmark`
   only produces CSV.  A lightweight `plot_benchmark.py` reads the CSV and calls
   matplotlib directly.  This keeps concerns separate and makes the plot step
   easy to run locally too.

3. **CI/CD wiring in `slides.yml`** – two extra shell commands after `generate-figures scenarios.yml`:
   ```
   generate-figures --benchmark benchmark_engines.yml --output benchmark_engines.csv
   plot-benchmark benchmark_engines.csv benchmark_engines.png
   ```
   The slides workflow now installs `'.[jax]'` so `jax-cpu` is available.

4. **`.gitignore`** – both `benchmark_engines.csv` and `benchmark_engines.png`
   are added so they are never accidentally committed.

5. **Removed the notebook** – `benchmark_engines.ipynb` was the wrong approach.
   The notebook reference was styling inspiration, not the implementation vehicle.

6. **NaN handling** – `plot_benchmark.py` skips NaN / blank CSV cells gracefully,
   so if an engine row fails the pipeline still produces a partial plot rather
   than aborting.
