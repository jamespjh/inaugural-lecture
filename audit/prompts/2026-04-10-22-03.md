# Prompt Summary – Benchmark table generation (2026-04-10)

## User instruction

Implement the changes described in GitHub issue "Generate tables of benchmarking
data for review":

- `--benchmark` switch on `generate-figures` CLI
- Warn if viz switches are given; ignore them in benchmark mode
- Output to stdout or file (warn if file doesn't end in `.csv`)
- Input YAML array values trigger parameter sweeps
- `[start:stop:step]` strings are expanded to arrays via `numpy.arange`
- Max two array parameters: first → columns, second → rows
- Multiple scenarios form the first (column) axis, labeled by a `key` field

## What was implemented

### `entry.py`
- Extracted `benchmark_scenario(args)` as a self-contained public function that
  creates a `ScenarioFactory`, sets up the scenario, and times a short
  `solve()` call using `benchmark_engine`.  Returns mean seconds as `float`.
- Refactored the `execute_scenario` benchmark branch to call
  `benchmark_scenario` instead of duplicating the timing logic.

### `generate.py`
- Added imports: `csv`, `re`, `sys`, `warnings`, `numpy`.
- `_VIZ_KEYS` constant: `{'visualise', 'video', 'outfile', 'format', 'duration'}`.
- `_parse_range_notation(value)`: regex-parses `[start:stop:step]` strings and
  returns a Python list (int or float elements); passes non-matching values
  through unchanged.
- `_expand_config_arrays(config)`: iterates config dict, skips `'key'` field,
  expands range notation, and splits into `base_config` (scalars) and
  `array_params` (ordered list of `(key, values)` tuples).
- `_build_benchmark_args(base_config, overrides)`: strips viz keys, merges
  overrides, sets `benchmark=True`, and calls `entry.parse_args`.
- `_write_benchmark_csv(headers, rows, output)`: writes CSV to file or stdout.
- `run_benchmark(configs, output)`: validates input, warns about viz keys,
  dispatches to `_run_single_scenario_benchmark` or
  `_run_multi_scenario_benchmark`.
- `_run_single_scenario_benchmark`: handles 0, 1, or 2 array parameters;
  warns if more than 2 are given.
- `_run_multi_scenario_benchmark`: scenarios become column headers (using
  `key` field); first array param becomes row axis.
- `generate_figures(yaml_file, benchmark, output)`: extended signature;
  `--benchmark` and `--output` added to CLI argparse; non-.csv output
  extension triggers a `UserWarning`.

### Fixtures
- `demo/tests/fixtures/benchmark_single.yaml` – single scenario with a method
  list for sweep tests.
- `demo/tests/fixtures/benchmark_multi.yaml` – two keyed scenarios with a
  method list for multi-scenario table tests.

### Tests
- `test_generate.py`: 15 new tests covering range notation, array expansion,
  viz warnings, all table shapes (no sweep / 1 param / 2 params /
  multi-scenario), `generate_figures` benchmark integration, and non-csv
  output warning.
- `test_entry.py`: 1 new test for `benchmark_scenario` return type and value.

## Key decisions

1. **`benchmark_scenario` as a standalone function** – makes the timing
   result programmatically accessible for sweep orchestration without
   needing to capture stdout.
2. **Strip viz keys before `parse_args`** – avoids `ValueError` from
   `--duration` without `--video`; simpler than suppressing errors.
3. **YAML `key` field** – skipped during `_expand_config_arrays` so it never
   reaches `entry.parse_args`; used only as the column label in multi-scenario
   output.
4. **`[start:stop:step]` → `numpy.arange`** – integer-valued arrays are
   converted to `int` for cleaner display.
5. **Column / row axis assignment** – first array param → column headers,
   second → row headers (per spec); for multi-scenario configs, scenarios
   become columns and first array param becomes rows.
6. **No changes to existing `run_batch` path** – `generate_figures` only
   calls `run_benchmark` when `benchmark=True`; all existing behaviour
   preserved.
