### Cascading issue discovered:
Moving jax to optional dependencies (done in earlier commit) created a new problem: `array_abstraction.py` still had `import jax` at module level. This caused test collection failures when jax is not installed. Also affected:
- `test_scenarios.py`: module-level `jax_factory = ScenarioFactory(engine='jax-cpu')` 
- `test_integrator.py`: hardcoded `jax-cpu` in `@pytest.mark.parametrize`

## Key Decisions

1. **Lazy import pattern for optional backends**: Moved `import jax` from module level into the specific methods that need it (`configure_jax()`, `array()`, `random_array()`). This is the right pattern for optional dependencies.

2. **Test filtering via AVAILABLE_ENGINES**: Used the existing `AVAILABLE_ENGINES` list from `engines.py` helper to conditionally include jax-cpu test cases, consistent with how other tests filter engines.

3. **Removing unused module-level jax instantiation**: The `jax_factory` variable in test_scenarios.py was unused - just removed it rather than adding a try/except.

4. **Pre-existing ffmpeg test failure**: The `test_viz.py::test_visualize` failure is pre-existing and documented - ffmpeg is not available in this sandbox environment.
