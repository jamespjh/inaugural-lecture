# Prompt: NxN Grid Visualisation for Stochastic Scenario Samples

## Issue
Issue #62: Add a grid visualisation option for lots of scenarios from a scenario
generator – specifically a 5×5 grid of the `scatter` scenario with 4 bodies.

## Conversation Summary
The user asked @copilot to make a plan for closing issue #62.  The copilot agent
(this session) was then tasked with implementing the required changes.

## Implementation Approach

### Codebase Understanding
The codebase has two main entry points:
- `entry.py` – the primary CLI (`teachgrav`) that parses args, creates scenarios,
  solves, and visualises.
- `generate.py` – YAML-driven batch generation for slides; converts YAML dicts to
  CLI args via `_config_to_force_args` and delegates to `entry`.

`visualisations/visualize.py` contains the existing `visualize`, `plot`, `animate`,
and `axes` helper functions.  A `grid_plot` function was added here.

`generate.py`'s `_config_to_force_args` already converts any integer YAML value
(e.g. `grid: 5`) to `--grid 5`, so **no changes were needed in generate.py**.

### Key Decisions
1. **Where to add `grid_plot`:** In `visualisations/visualize.py`, consistent with
   `plot` and `animate`.  It re-uses `_equal_aspect_limits` and `_apply_axis_style`
   for styling.

2. **Cell size:** Fixed at 2.5 inches per subplot.  This keeps the figure
   manageable for a 5×5 grid (12.5×12.5 inches) while remaining readable.

3. **Per-cell axis limits:** Each cell is auto-scaled independently using
   `_equal_aspect_limits`.  Since each stochastic scenario sample has different
   extents, a shared axis would make most cells tiny.

4. **Options forwarding:** `args.visualise` ('trail'/'dot') is forwarded to
   `grid_plot` via `_execute_grid_scenario`, allowing the user to choose the
   style.  The issue requested trail, but dot is supported too.

5. **Grid mode with no outfile:** Modified `_validate_args` so that when
   `--grid` is set without `--outfile`, `args.visualise` is NOT cleared.  This
   allows interactive display (consistent with other visualisation paths).

6. **Validation:** `--grid < 1` raises a `ValueError`, consistent with
   `--n-bodies` validation.

7. **`_execute_grid_scenario`:** A clean helper function in `entry.py` that
   creates N² scenarios by calling `factory.create_scenario` in a loop (the
   factory's random state advances naturally), integrates each, and calls
   `grid_plot`.

### Tests
- `test_viz.py`: Tests for `grid_plot` covering trail/dot options, 1×1/2×2/3×3
  grids, PNG file creation, and invalid-option errors.  All use fake trajectories
  to avoid the missing `numba` dependency.
- `test_entry.py`: Tests for `--grid` arg parsing, zero/negative rejection,
  `_execute_grid_scenario` invocation count, and options forwarding.

### Fixtures
- `generate_grid.yaml`: Canonical 5×5 scatter/4-body example for use in the
  slideshow YAML pipeline.
