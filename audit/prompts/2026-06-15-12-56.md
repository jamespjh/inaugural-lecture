# Prompt summary: Add --moons-per-planet CLI switch

**Date:** 2026-06-15

## User request

> @copilot We need to add cli-switches to pass the moon-count-array

## Key decisions and reasoning

- Followed the exact same pattern as `--n-bodies` / `scatter`: a dedicated
  `argparse` argument with `nargs='+'` and `type=int`, a kwarg injection in
  `execute_scenario`, and a guard in `_validate_args`.
- Used `nargs='+'` (one or more integers) rather than `nargs='*'` because an
  empty list would be semantically meaningless and is already handled by the
  default `None` (which lets the scenario fall back to its own default).
- Validation is kept symmetric with `--n-bodies`: raise `ValueError` when the
  flag is passed with a non-solar_system scenario, so error messages are
  consistent.
- Four existing mock `Args` classes in `test_entry.py` lacked the new
  attribute, causing `AttributeError`; added `moons_per_planet = None` to each.
- Added three new test functions mirroring the `n_bodies` tests.
- The pre-existing `numba` import failure in one test is unrelated to this
  change.
