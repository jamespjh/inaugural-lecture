## Key Decisions and Reasoning

### scipy callback vs. custom loop
Used scipy.optimize.minimize's `callback` parameter rather than a custom
optimisation loop. This requires zero changes to the mathematical core and
keeps the training code minimal. The callback is called once per optimisation
iteration (not per function evaluation), which naturally produces a tractable
number of frames.

### Dedicated `--convergence-video` argument
Rather than repurposing `--outfile`/`--video` (which have clear meaning for
the simulation path), a dedicated `--convergence-video` argument is added.
This keeps the existing validation tests passing and avoids any ambiguity
between simulation output and training-convergence output.

### Stability filtering
Early training checkpoints routinely have extreme parameter values (G or power
far from their true values) leading to overflow and Inf/NaN in trajectories.
The implementation silently skips such frames rather than crashing. The viz
function also uses `np.isfinite` when computing axis bounds as a safety net.

### `integrate_trajectory` model parameter
Adding an optional `model=` parameter to `integrate_trajectory` allows
checkpoint models to be passed directly without writing temporary YAML files.
This is cleaner and faster than the alternative.

### Complexity refactoring
The existing `_validate_args` function was already at the complexity limit
(max-complexity = 15). Adding new validation checks for the convergence video
exceeded the limit. This was resolved by extracting a `_validate_train_args`
helper, which also improves readability.

### Slide integration
The `video-credit` Quarto shortcode (already used in part1.qmd) was reused for
consistency. The generation command is documented as a YAML comment in
`scenarios.yml`.
